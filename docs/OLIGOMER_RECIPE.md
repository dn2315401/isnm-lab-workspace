# 올리고머 합성 조성 — 2026-11-24

기존 배치 편집 페이지 안에 A/B 조성 자동 계산을 추가했습니다. 새 배치는 작용기 몰비가 기본이며, 물질 몰비와 질량비를 선택할 수 있습니다. A/B 원료·사용 시약과 물성은 기존 MaterialPicker/selectionRow에서 가져옵니다. 여러 작용기가 있으면 계산할 종류를 직접 고릅니다. 순도 보정은 하지 않습니다.

- 계산: `src/oligomer-recipe.ts`. 내부 질량은 g, 부피는 mL. 중간 반올림 없이 계산합니다. 부족한 분자량·작용기·밀도는 추정하지 않습니다. 질량비는 분자량 없이 계산 가능합니다.
- 촉매: 기준 물질 대비 wt%, A+B 대비 wt%, 직접 입력, drops. A+B 기준에는 첨가제·촉매·용매·세척액이 들어가지 않습니다. 액체 상태와 유효한 밀도가 확인된 때만 질량/부피를 환산합니다. drops는 숫자와 방식만 보관하고 임의 질량/부피로 바꾸지 않습니다.
- 용매 부피는 사용자가 입력한 mL로 고정됩니다. 추가 원료는 별도 첨가제로 표시하며 자동 A/B 계산에 참여하지 않습니다. RT는 문자열 그대로 저장합니다.
- `recipe`는 입력 기준·원료 행 ID·비율·단위, `recipeResult`는 계산 결과를 보관합니다. `ingredients`에 동일한 투입량과 기존 materialId/reagentId를 기록하여 공용 원료 사용 이력 연결을 유지합니다. 물성·선택 시약은 각 행의 스냅샷입니다. DB 수정으로 과거 배치가 자동 갱신되지 않습니다.
- `recipe`가 없는 기존 배치는 자동 전환하지 않습니다. 원래 조성·촉매·원료·첨부 및 연결 정보를 보존하며, 사용자가 자동 계산 사용을 명시한 경우에만 새 입력 방식으로 전환합니다. 기존 계획량 필드는 저장 데이터에서 삭제하지 않지만 새 입력 UI에는 투입량 하나만 표시합니다.
- Mn/Mw가 모두 유효하면 PDI=Mw/Mn, 나머지 분석값은 선택 입력입니다. 기존 분석 ID 연결, 첨부 방식·크기 제한, 상태, 변경 이력은 유지됩니다.
- 배치 본문과 첨부는 기존 브라우저 저장 방식을 유지합니다. 원료 DB/사용 이력의 공유 연결을 전체 배치 본문 공유 저장으로 설명하지 않습니다.

`npm run test:oligomer`는 소스 원료 카탈로그 RM82/EDDT, 명시적인 가상 PBB 4작용기 fixture의 두 기준 동등성, 질량비·누락 물성·잘못된 비율, 촉매 wt%·직접 입력·drops, 용매 고정, RT/PDI, 저장/재조회/수정 이력/과거 스냅샷 보존, 실제 편집 컴포넌트의 원료 선택과 세척액 핸들러를 검사합니다. PBB fixture의 물성은 실제 DB에 추가하지 않습니다.

브라우저 조작 도구가 없어 실제 Chrome의 화면 배치와 클릭은 수동 검증하지 못했습니다. JSX 핸들러·모델·저장 검사와 TypeScript/프로덕션 빌드로 검증합니다.
