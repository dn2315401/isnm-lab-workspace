# 올리고머 합성 조성 — 2026-11-24

기존 배치 편집 페이지 안에 A/B 조성 자동 계산을 추가했습니다. 새 배치는 물질 몰비와 작용기 몰비를 동시에 표시하며 A=1로 정규화합니다. 마지막으로 편집한 기준과 정밀한 입력값 하나만 저장하고 상대 기준은 읽을 때 도출합니다. 기준 드롭다운과 새 질량비 입력은 제거했으며, 기존 질량비 배치는 원래 기준 그대로 보존합니다. A/B 원료·사용 시약과 물성은 기존 MaterialPicker/selectionRow에서 가져옵니다. 여러 작용기가 있으면 계산할 종류를 직접 고릅니다. 순도 보정은 하지 않습니다.

- 계산: `src/oligomer-recipe.ts`. 내부 질량은 g, 부피는 mL. 중간 반올림 없이 계산합니다. 부족한 분자량·작용기·밀도는 추정하지 않습니다. 질량비는 분자량 없이 계산 가능합니다.
- 촉매: 기준 물질 대비 wt%, A+B 대비 wt%, 직접 입력, drops. A+B 기준에는 첨가제·촉매·용매·세척액이 들어가지 않습니다. wt% 자동 계산의 부피 표시는 액체 상태와 유효한 밀도가 확인된 때만 환산합니다. 직접 입력은 환산 없이 그대로 기록합니다. drops는 숫자와 방식만 보관하고 임의 질량/부피로 바꾸지 않습니다.
- 용매 부피는 사용자가 입력한 mL로 고정됩니다. 추가 원료는 별도 첨가제로 표시하며 자동 A/B 계산에 참여하지 않습니다. RT는 문자열 그대로 저장합니다.
- `recipe`는 입력 기준·원료 행 ID·비율·단위, `recipeResult`는 계산 결과를 보관합니다. `ingredients`에 동일한 투입량과 기존 materialId/reagentId를 기록하여 공용 원료 사용 이력 연결을 유지합니다. 물성·선택 시약은 각 행의 스냅샷입니다. DB 수정으로 과거 배치가 자동 갱신되지 않습니다.
- `recipe`가 없는 기존 배치는 자동 전환하지 않습니다. 원래 조성·촉매·원료·첨부 및 연결 정보를 보존하며, 사용자가 자동 계산 사용을 명시한 경우에만 새 입력 방식으로 전환합니다. 기존 계획량 필드는 저장 데이터에서 삭제하지 않지만 새 입력 UI에는 투입량 하나만 표시합니다.
- Mn/Mw가 모두 유효하면 PDI=Mw/Mn, 나머지 분석값은 선택 입력입니다. 기존 분석 ID 연결, 첨부 방식·크기 제한, 상태, 변경 이력은 유지됩니다.
- 배치 본문과 첨부는 기존 브라우저 저장 방식을 유지합니다. 원료 DB/사용 이력의 공유 연결을 전체 배치 본문 공유 저장으로 설명하지 않습니다.

브라우저 조작 도구가 없어 실제 Chrome의 화면 배치와 클릭은 수동 검증하지 못했습니다. JSX 핸들러·모델·저장 검사와 TypeScript/프로덕션 빌드로 검증합니다.

추가 UI 개선: 작용기 한 종류는 자동 선택하고 둘 이상일 때만 선택창을 표시합니다. A/B 선택 버튼은 원료명을 표시하며 원료 상세 DB 링크를 유지합니다. 결과 표는 mmol 최대 소수 3자리, g 최대 소수 4자리로 표시하고 내부 저장·계산은 반올림하지 않습니다. 질량비만 결과 하단에 참고로 표시합니다. `recipeRatios`는 저장 상태를 변경하지 않는 순수 함수이고, `editRecipeRatio`가 사용자 입력 시에만 단일 기준값을 갱신하므로 양방향 effect 루프가 없습니다.

## 예비 계산·직접 입력 개선

- 새 기록은 `recordType: preliminary`, 과거에 필드가 없는 기록은 합성 기록으로 취급합니다. 상태와 기록 유형은 별개이며 토글은 입력 내용을 삭제하지 않습니다.
- 예비 계산에서는 합성일/상태/분석을 숨깁니다. 계산이 완성되면 이름만 있는 기록도 저장할 수 있고, 이름이나 계산이 미완성이면 임시저장할 수 있습니다. 기존 예정일은 데이터에 남기되 별도 입력은 제거했습니다. 합성일은 선택 입력이며 날짜로 상태를 바꾸지 않습니다.
- `synthesisFromPreliminary`는 ID/수정 이력을 새로 시작하는 복사본을 생성하고 `sourcePreliminaryId`로 원본을 참조합니다. 원본 및 첨부 원본은 그대로 둡니다. 새 합성 기록은 합성 예정 상태입니다.
- 촉매 직접 입력은 mg/g/µL/mL의 원문 숫자·단위를 그대로 recipe와 사용 행에 저장합니다. 물리 상태·밀도·재고로 제한하거나 질량/부피 환산을 강제하지 않습니다. 자동 환산 영역은 숨깁니다. 방울 수도 그대로 보관합니다. wt% 계산과 액체 부피 환산에만 필요한 데이터 검증을 유지합니다.
- 올리고머 페이지의 원료 선택은 `MaterialPicker unrestricted`로 모든 등록 물질을 선택할 수 있습니다. 사용 시약은 선택이며 다른 페이지의 기본 선택 정책은 변경하지 않았습니다. 물성은 실제 값이 등록된 항목만 간결하게 표시합니다.
- 예비 계산은 배치 집계에서 제외하고 사용 이력에 계획량으로만 연결합니다. 클라이언트 UI와 `/outputs` 서버 검증 모두 실제 올리고머 재고 생성을 차단합니다. 원료 재고 차감 기능은 추가하지 않았습니다.
