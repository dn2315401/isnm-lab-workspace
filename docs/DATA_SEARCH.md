# 데이터 검색 시스템 — 11-14 작업 보고

## 현재 저장 구조와 범위

React 19 + TypeScript + Vite의 기존 해시 라우팅과 공통 화면을 재사용했습니다. 현재 앱에는 공유 데이터베이스, 서버 검색 API, 로그인·프로젝트 접근 권한 서버가 없습니다. 원본은 각 브라우저의 localStorage와 기존 첨부 메타데이터에 저장됩니다.

이번 변경은 새 DB를 도입하거나 실험 기록을 복제하지 않습니다. 검색 화면은 읽기 전용 어댑터를 통해 저장 기록을 정규화해 조회합니다. 검색 실행·상세 열기·비교로 기존 프로젝트, 조성, 계산, 합성, 샘플 ID를 새로 만들거나 원본을 갱신하지 않습니다. 미저장 기본 예시를 검색에 생성하지 않으며, 저장된 예시도 기본 결과에서 제외합니다.

## 구현된 기능

- 기본 통합 검색: ID, 이름, 별칭, CAS, 원료명, Lot, 메타데이터. 대소문자·앞뒤 공백·일반 특수문자 지원.
- 정확 ID → 이름 → 메타데이터 → 연결 관계 순으로 검색 우선순위 적용. 같은 이름의 다른 ID를 병합하지 않으며, 같은 기록의 중복 결과는 제거.
- 프로젝트/원료/Lot/올리고머/조성 버전/계산/합성/샘플 그룹/개별 샘플/공정/측정/수치 결과/파일/분석 참조를 구분.
- `2026`, `2026-11`, `2026-11-13`, `/`와 `.` 날짜, `시작 ~ 종료` 인식. ID는 날짜로 오인하지 않음. 일반 검색어·날짜 모드 명시 선택 가능.
- 실제 수행일/생성일/수정일/예정일 구분. 한국시간 날짜 경계와 기간 양끝 포함. 실제 수행일 누락을 생성일로 대체하지 않음.
- 프로젝트·연구자·상태 다중 선택: 같은 항목은 OR, 서로 다른 항목은 AND. 날짜/유형/검색 범위/보관 조건 조합과 개별 조건 해제.
- 올리고머 Mn/Mw/PDI, 원료 포함·제외/Lot/역할, 조성 버전·동일 버전의 원료 wt% 및 전체/용매 제외 분모 검증.
- 샘플 형태, 목표/실제 두께, 폭·길이·직경, 연신율/연신비, 공정 종류·기록 온도 필터. 미기록 수치는 0으로 간주하지 않음.
- 같은 측정 기록에서 장비·모드·분석 완료 상태를 함께 검증. 같은 결과 기록에서 항목·값·단위·온도·주파수를 함께 검증. Pa/kPa/MPa/GPa 및 °C/K/°F, Hz/kHz/MHz/mHz 변환 지원.
- `sample.analysis` 같은 참조 문구를 실제 Measurement 또는 분석 완료로 만들지 않음. 독립된 참조 레코드는 ‘분석 참조’로 구분.
- 20/50/100건 단위 페이지 응답, 관련도·날짜·이름·ID 정렬과 안정적인 보조 키. 선택한 기록의 상세는 별도 조회.
- 데이터 유형별 읽기 전용 상세 탭, 실제 연결 기록 탐색, 순환 방지, 원본 관리 화면으로 이동. 조성 관리 화면은 지정한 ID와 버전을 정확히 로드.
- 검색 조건/정렬/페이지/선택을 sessionStorage와 URL에 보존. 최신 요청만 화면에 적용하고 이전 요청은 취소.
- 현재 페이지/검색 전체 결과 CSV 내보내기. 적용 조건·한국시간·범위 명시, 스프레드시트 수식 주입 방지.
- 최대 5개 샘플 비교: 계획 조성/두께/연신/제작 조건. 측정을 자동 대표값으로 선택하지 않음.
- 저장된 구조화 곡선에 필요한 장비·모드·축·단위·조건·처리 방법이 모두 있으며 호환될 때만 비교 그래프 표시.
- 초기/검색 중/빈 결과/검색 실패/누락된 원본/일부 데이터 읽기 실패를 구분. 오류가 나도 조건과 원본 유지.

## 파일과 기존 기능 연결

- `src/research-search.ts`: 원본 기반 정규화 인덱스, 관계, 수치·복합 조건, 정렬, 페이지·상세 조회 계약과 로컬 어댑터.
- `src/search-dates.ts`: 엄격한 날짜 검증과 한국시간 변환.
- `src/search-records.ts`: Measurement, AnalysisResult, FileMetadata의 호환 스키마.
- `src/search-http.ts`: 실제 서버가 준비되면 사용할 HTTP 어댑터. 기본 앱에는 활성화하지 않음.
- `src/search-comparison.ts`: 곡선 비교 호환성 검증.
- `src/ResearchSearch.tsx`, `src/research-search.css`: 검색 화면·상태·필터·상세·내보내기.
- `src/ResearchComparison.tsx`: 시료 비교와 호환 곡선 표시.
- `src/Formulation.tsx`, `src/main.tsx`: 검색 조건 URL 및 조성 버전별 원본 이동 호환 확장. 다른 관리 기능을 제거하지 않음.
- `tests/search.test.cjs`, `scripts/test-search.mjs`: 검색 회귀 검증.

실험 원본 저장 형식은 변경하지 않았습니다. 새 검색 스키마는 앞으로 실제 측정/결과/파일 관리 API와 연결하기 위한 계약이며 검색 실행만으로 새 저장소나 가상 측정을 생성하지 않습니다.

## 읽는 원본 키

기존: `isnm-projects`, `isnm-material-library-v1`, `isnm-oligomer-batches-v1`, `isnm-formulations`, `isnm-research-v1`, `isnm-equipment-v1`.

별도 실측 기록이 존재할 때만 읽는 키: `isnm-measurements-v1`, `isnm-analysis-results-v1`, `isnm-process-records-v1`, `isnm-sample-groups-v1`, `isnm-file-metadata-v1`. 없는 키는 빈 목록이며 기본값을 저장하지 않습니다.

연결: 원료/Lot/올리고머 → 해당 조성 버전 → 계산 → 합성 → 동일 Sample ID → 개별 공정/Measurement → Result/File. 프로젝트 노드를 거쳐 무관한 기록까지 검색 연관도를 확장하지 않습니다.

## 검증

`npm run test:search`: 날짜 유효성·연월일·KST 경계, ID 우선순위, 연결/중복, 프로젝트·기간 조합, 수행일 누락, 동일 버전 wt%, 단위 변환, 측정과 참조 구분, 동일 측정/결과의 조건 결합, 페이지·지연 상세, 요청 취소, 잘못된 원본 경고, 원본 불변, 곡선 조건 불일치, HTTP 403/404/500·응답 오류를 격리된 테스트 데이터로 확인합니다.

`npm run test:calculator`: 기존 계산 기능 회귀 검사.

`npm run build`: TypeScript와 Vite 빌드.

브라우저 실제 클릭·반응형 스크린샷 검증은 이 실행 환경의 브라우저 검증 도구가 없어 수행하지 못했습니다. 서버 권한 시나리오는 실제 인증 서버가 없어 검증 대상이 아닙니다. HTTP 어댑터의 오류 처리는 모의 응답으로 검사합니다.

## 아직 없는 기능과 다음 단계

- 실제 공유 DB·서버 인덱스·서버 페이지네이션: 기존 앱에 DB/API가 없어 이번에 임의로 만들지 않았습니다. 현재 로컬 어댑터는 최초 조회 시 브라우저 저장 데이터를 읽고 캐시하며, 필터 변경 시 페이지 결과만 UI에 전달합니다. 실제 운영 규모의 서버 검색과 같다고 표시하지 않습니다.
- 서버 인증·프로젝트 ACL·안전한 파일 다운로드: 클라이언트 필터는 접근 제어가 아닙니다. 서버의 목록·건수·상세·관계·파일 요청에서 각각 권한 검사가 필요합니다.
- 장비 원본 자동 파싱과 대용량 원격 그래프 스트리밍: 현재는 저장된 구조화 곡선만 비교합니다. 원본 이미지나 파일명을 임의의 수치로 해석하지 않습니다.
- 실제 파일 보관소: 기존 저장 파일의 다운로드 또는 메타데이터를 조회합니다. 보안 객체 저장소 연동은 미구현입니다.

다음 단계는 인증/공유 DB와 원본 데이터 관리 API의 계약을 정한 뒤 `SearchRepository`의 로컬 구현을 HTTP 구현으로 교체하는 것입니다. 현재 화면/필터/상세/비교 코드를 유지할 수 있도록 경계를 분리했습니다.
