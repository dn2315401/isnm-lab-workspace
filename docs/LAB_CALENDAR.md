# 연구실 캘린더 · 2026-11-23 v3

홈 배너와 `#calendar`는 동일한 연구실 일정을 사용합니다. 하단 장비 예약 캘린더는 기존 `isnm-bookings` 로컬 기록만 사용합니다. 기존 프로젝트·조성·합성·장비 예약 데이터는 변경하거나 서버로 자동 전송하지 않습니다.

## 로그인과 구성원

사이트의 ChatGPT 로그인으로 실제 계정 ID를 확인합니다. 최초 관리자는 Sites 런타임의 `CALENDAR_OWNER_EMAIL`과 일치하는 로그인 계정입니다. 값은 저장소에 넣지 않습니다. 관리자의 구성원 관리에서 실제 계정 이메일을 허용하거나 로그인 후 대기 중인 계정을 승인합니다. 이메일 허용은 자동 메일 발송이 아닙니다. 회원별 연구실 전체 일정 생성 권한을 지정합니다.

로그인은 연구실 구성원 승인과 구분합니다. 로그인하지 않은 사용자와 미승인 사용자는 일정 API를 조회하거나 수정할 수 없습니다. 개인 일정은 소유자만 수정·삭제합니다. 비공개 일정은 서버 조회 단계에서 다른 사용자에게 반환하지 않습니다. 수업의 공개 제목을 ‘수업’으로 지정하면 타 구성원 응답에서 원래 과목명·장소·메모를 제거합니다. 연구실 전체 일정은 작성자 또는 관리자만 수정합니다. 클라이언트가 전송한 소유자·작성자 ID는 신뢰하지 않습니다.

## 저장과 반복

Cloudflare D1의 `calendar_events`, `calendar_members`, `calendar_invites` 테이블을 사용합니다. 데이터는 `drizzle/0000_lab_calendar.sql`의 추가 전용 마이그레이션으로 생성합니다. API 요청 중 테이블을 만들거나 기존 테이블을 변경하지 않습니다. 일정의 반복 규칙과 회차별 예외를 JSON으로 저장하므로 회차별 DB 레코드를 대량 생성하지 않습니다. 반복 주기는 실제 최초 시작일 기준이며, 월간 n번째 요일도 지원합니다. 날짜는 한국 시간으로 취급하고 `startAt`·`endAt`에는 `+09:00`을 포함합니다.

반복 수정/삭제는 한 회차, 이후, 전체 범위를 지원합니다. 이후 범위 수정은 기존 규칙을 종료하고 새 규칙을 생성합니다. 개별 회차 이동은 원래 발생일을 예외 키로 유지합니다. 수정 충돌은 revision으로 감지합니다. SQL은 바인딩 매개변수를 사용하고, 교차 출처 쓰기 요청은 차단합니다. 개인정보 응답은 `Cache-Control: no-store`입니다.

수업 시간표는 일정과 동일한 저장소의 주간 반복 이벤트로 등록하고 `classScheduleId`와 학기 정보를 연결합니다. 별도의 중복 수업 레코드는 생성하지 않습니다. 전체 시간표 교체는 DB 배치로 적용하며, 개별 휴강과 보강은 회차 예외 또는 별도 일정으로 처리합니다. 교체 전에 예외가 초기화됨을 확인합니다. 같은 시간의 수업 행은 저장 전에 차단합니다.

## 빌드와 검증

`npm run build`는 기존 Vite UI와 `dist/server/index.js` Worker를 함께 생성합니다. 기존 앱 자산은 Worker에 포함해 기존 URL에서 제공합니다. 실제 배포에는 프로젝트 ID를 유지한 `.openai/hosting.json`의 D1 바인딩 설정과 SQL 마이그레이션을 포함합니다. `.env.example`은 필요한 환경변수 이름만 기록합니다.

- `npm run test:calendar`: 실제 SQLite를 사용하는 API 권한·반복·예외·시간표·충돌 테스트
- `npm run check:calendar`: Worker 타입 검사
- 기존 `test:calculator`, `test:materials`, `test:search` 유지

이 변경은 기존 브라우저 로컬 실험 데이터를 공용 DB로 이전하지 않습니다. 실제 로그인에 따른 배포 환경 검증은 로그인한 사용자의 확인이 필요합니다.
