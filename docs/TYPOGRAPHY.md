# 전체 글자 크기 조정

11-14 작업 브랜치에서 적용한 가독성 수정입니다. 이름과 작업 위치는 유지합니다.

## 조사한 기준

- [GOV.UK Type scale](https://design-system.service.gov.uk/styles/type-scale/): 역할에 따른 글자 단계와 줄높이를 사용하고 em/rem 같은 상대 단위를 권장합니다. 일반 본문 19px, 작은 본문 16px 등을 사용합니다.
- [W3C WCAG 1.4.4 Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html): 글자를 200%까지 키워도 내용과 기능을 잃지 않아야 합니다.
- [W3C WCAG 1.4.12 Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html): 사용자가 줄간격·자간 등을 바꾸더라도 잘리거나 겹치지 않도록 설계해야 합니다. 모든 사이트의 기본 글자 크기를 특정 px로 규정하는 기준은 아닙니다.

## 이 앱에 적용한 판단

기존 홈·조성표·계산기에는 6~11px 글자가 많이 있었습니다. 전체 화면을 같은 비율로 확대하는 대신 작은 글자에 더 큰 보정을 적용하고 큰 제목과 주요 숫자의 변화는 작게 유지했습니다.

기본 브라우저 글자 크기가 16px일 때:

| 용도 | 조정 기준 |
| --- | --- |
| 보조 캡션 | 최소 12px |
| Lot·날짜·메타 정보 | 12~13px |
| 메뉴·표·입력 레이블 | 14~16px |
| 본문과 주요 설명 | 15~16px 중심 |
| 구역 제목 | 18~20px 중심 |
| 페이지 제목 | 대체로 24~32px, 큰 기존 제목을 무조건 확대하지 않음 |

장비 일러스트 내부의 장식 글자나 로고, 아이콘 전용으로 감춘 모바일 메뉴 글자는 별도로 유지했습니다. 작은 화면이라고 주요 정보를 다시 6~10px로 축소하지 않습니다.

## 구현

- `src/typography.css`: 공통 rem 글자 토큰, 줄높이, 큰 글자에 맞춘 입력칸·행 높이·줄바꿈·스크롤 보정.
- 기존 CSS의 `font-size`를 공통 토큰으로 정리: 홈, 조성 정보, 프로젝트/계산기, 데이터 검색, 원료물질, 올리고머 배치, 장비 예약, 버전 정보.
- 루트는 `100%`로 설정해 사용자의 브라우저 기본 글자 설정을 따릅니다. 주요 문단 줄높이는 1.65, 일반 UI는 1.5를 기준으로 합니다.
- 표는 내용을 숨기는 대신 기존 가로 스크롤을 사용하고 필요한 열 너비를 확보합니다.
- 계산기 하단 버튼, 검색 필터, 모바일 헤더 등은 줄바꿈할 수 있게 조정했습니다.
- 좁은 화면에서 카드·조건 패널을 세로로 배치하고 사이드바는 내용이 길면 스크롤할 수 있게 했습니다.
- 측정 비교 그래프의 축 글자를 키우고 작은 화면에서는 그래프를 가로로 스크롤하도록 했습니다.
- 본문에 쓰이는 매우 옅은 보조 글자 일부를 조금 진하게 조정했습니다.

## 검증 범위

프로덕션 빌드와 CSS 파싱, 사용한 글자 토큰의 정의 및 작은 글자 선언을 확인했습니다. 이 변경은 실험 데이터나 계산·검색 로직을 바꾸지 않습니다. 실제 브라우저의 화면별 배치와 200% 확대/사용자 자간 설정은 현재 관리형 환경의 브라우저 도구가 없어 직접 검증하지 못했으며, WCAG 전체 준수를 주장하지 않습니다.
