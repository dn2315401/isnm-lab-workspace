# 전체 날짜 입력 점검 및 공통화 — 2026-11-24 v1

## 원인과 변경

원료 화면만 MaterialDateInput을 사용하고 다른 화면은 브라우저 기본 input[type=date]를 사용했습니다. 기본 날짜 입력은 연·월·일을 각각 편집하는 컨트롤이므로 숫자 8개를 연속 입력하면 연도 세그먼트에 여러 숫자가 들어갈 수 있습니다. 기존 원료 전용 입력도 포커스 여부에 따라 숫자/구분자 표시를 바꿨고, 일부 저장 경로는 부분 입력을 받을 수 있었습니다.

이제 전체 날짜 입력은 `src/DateInput.tsx`를 사용합니다. 기존 MaterialDateInput은 같은 컴포넌트를 가리키는 호환 export입니다. 브라우저 native 날짜 입력은 공통 컴포넌트 내부 달력 선택기에만 남아 있고 직접 입력에는 사용하지 않습니다.

- 화면 입력: YYYY.MM.DD. 숫자를 4/2/2자리로 나누고 숫자는 최대 8개만 유지합니다.
- 저장 및 onChange: 유효한 YYYY-MM-DD만 전달합니다. 선택 입력을 완전히 지우면 빈 문자열을 전달합니다.
- 미완성·잘못된 날짜는 편집 중인 로컬 텍스트로 유지하고 저장 상태로 전달하지 않습니다. 수동 저장/검색에서는 checkValidity/reportValidity와 ensureDateInputs로 이전 값이 잘못 저장되는 일을 막습니다.
- 윤년·월별 말일은 숫자 계산으로 검증하며 잘못된 날짜를 다음 달로 보정하지 않습니다.
- 구분자 입력·붙여넣기·백스페이스·Delete·선택 영역 수정·커서 위치·필수 입력·min/max를 공통 처리합니다.
- 직접 입력과 달력은 하나의 편집 텍스트에서 날짜를 도출하여 동기화합니다. 범위를 바꿔 이전에 보류된 날짜가 유효해지는 경우도 반영합니다.
- 날짜 전용 값에는 Date 생성자·UTC/로컬 시간대 변환을 적용하지 않습니다. 메타데이터의 실제 타임스탬프는 기존 한국시간 검색 처리를 유지합니다.

월/연도만 검색하는 제어는 의미가 다르므로 기존 월 선택과 연도 숫자 입력을 유지합니다. 날짜를 직접 입력하는 별도 native type=date는 남아 있지 않은지 자동 검사합니다.

## 공통 로직·저장·기존 데이터

`src/date-only.ts`가 날짜 유효성, 표시, 안전한 기존 문자열 해석, 편집과 커서, 저장용 변환을 담당합니다. `material-dates.ts`는 같은 로직을 재사용합니다. `search-dates.ts`는 같은 실제 날짜 검증을 사용하며 8자리·점·하이픈·슬래시 검색과 기간 비교를 지원합니다. 시작일이 종료일보다 늦으면 안내합니다.

기존 ISO 문자열은 그대로 사용하고, 명확한 YYYYMMDD·YYYY.MM.DD·YYYY-MM-DD·YYYY/MM/DD 및 명확한 단일 자리 월/일의 기존 값은 표시용으로 안전하게 해석합니다. 의미 불명의 문자열은 원문을 표시하고 오류로 안내하며 저장 시 명시적인 수정을 요구합니다. 화면을 열었다고 원본을 덮어쓰거나 전체 자료를 마이그레이션하지 않습니다.

배치 저장, 원료·시약 저장, 실제 장비 실험 API 등 명시적 저장 경로는 안전하게 해석 가능한 날짜만 ISO로 변환합니다. 신규 입력은 공통 컴포넌트에서 이미 ISO로 전달됩니다. DB 스키마와 과거 스냅샷은 변경하지 않았습니다. 기존 원료/사용 이력 테스트에서 원본·스냅샷 보존을 재검증했습니다.

기존 날짜 타임스탬프(createdAt 등)는 시간 정보를 버리지 않습니다. 검색용 날짜 전용 값과 타임스탬프 변환 경로를 구분합니다. 날짜만 있는 잘못된 값은 JavaScript Date에 넘겨 자동 보정하지 않습니다.
