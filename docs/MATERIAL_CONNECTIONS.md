# 전역 물질 연결 · 2026-11-24 v1

## 변경 전과 변경 후

| 영역 | 이전 | 변경 후 |
| --- | --- | --- |
| 원료 DB | 브라우저별 원료 복사본 | 공용 D1 원료 기준 데이터, 로컬은 캐시와 원본 백업 |
| 올리고머 촉매 바로가기 | DBU 등의 문자열 입력 | 공용 원료의 고유 ID 조회·연결. 중복 이름은 선택 요구 |
| 용매·세척액 | 자유 텍스트 | 동일한 공용 선택창, 원료 ID와 선택적 Lot 참조 |
| 조성·조성계산기 | 페이지별 선택 UI, 일부 첫 Lot 자동 선택 | 공통 `MaterialPicker`, CAS·ID·제조사·Lot 검색 및 등록 후 복귀 |
| 실제 합성 | 계산 스냅샷의 원료·Lot만 유지 | 계획 스냅샷 유지 + 실제 원료·Lot 별도 확인·사용량 기록 |
| 자체 합성 올리고머 | 배치를 가상 원료로 구성 | 실제 완료 배치를 명시적으로 등록, 동일 원료 종류 + 배치별 Lot |
| 사용 이력 | 현재 브라우저의 연결만 조회 | 공용 사용 기록, 계획/실제량, 원본 스냅샷과 역방향 참조 |

명칭은 표시 정보이며 연결 키는 원료 ID입니다. 실제 Lot이 없으면 `lot_id`는 NULL이며 ‘Lot 미등록 / 미지정’으로 표시합니다. 목록 표시용 가상 행은 실제 제조 Lot으로 등록하지 않습니다. Lot 미등록 시약의 기존 보관·용량·잔량·물성·메모도 별도의 미지정 정보로 보존합니다.

## 공통 데이터 계층과 화면

`src/materials/service.ts`는 공용 API, 캐시 갱신, 이전, 사용 이력 동기화를 관리합니다. `MaterialPicker`를 올리고머·촉매·용매·세척액·조성계산기·조성 페이지·실제 합성 원료 확인에서 공통 사용합니다. 새 원료 등록도 공용 저장 API를 사용하며 원래 폼 상태를 유지합니다. 원료 ID가 없는 텍스트를 등록된 물질로 취급하지 않습니다.

촉매 요약은 `catalystUsageId`를 통해 원료 행 하나를 참조합니다. 함량·단위 변경은 같은 행에 반영합니다. 명시적으로 여러 번 추가하거나 역할·Lot이 다른 사용 행은 서로 다른 사용 ID로 보존합니다. wt% 같은 비율을 실제 질량으로 추정하지 않습니다. 실제 질량은 따로 입력해야 합니다.

기본 정보의 최신 명칭은 원료 링크에서 갱신되지만, 저장한 계산의 분자량·밀도·작용기·계산 조건과 과거 사용량은 스냅샷으로 유지합니다. 사용자가 실제 Lot이나 현재 계산의 물성을 명시적으로 변경할 때만 해당 작업의 스냅샷을 변경합니다.

## D1 테이블과 관계

추가 전용 `drizzle/0001_material_connections.sql`을 적용합니다. 기존 캘린더 마이그레이션은 변경하지 않습니다.

- `material_entities`: 공용 원료, 고유 ID, CAS, 기본 정보와 revision
- `material_lots`: 원료 FK, 고유 Lot ID, 제조사·Lot 번호, 원본 합성 FK
- `material_experiments`: 원본 종류·기기별 ID, 프로젝트 참조, 원본 스냅샷
- `material_usages`: 사용 ID, 실험 FK, 원료 FK, 선택적 Lot FK, 역할·계획량·실제량·단위
- `material_aliases`, `material_lot_aliases`: 이전 ID에서 확정된 공용 ID로의 매핑
- `material_experiment_history`: 기존 실험 스냅샷 revision 보관
- `material_links`: 계산→합성→샘플→측정·분석의 정방향/역방향 참조

사용 기록의 `(material_id, lot_id)`는 Lot 테이블의 동일 조합을 참조하는 복합 외래키로 검증합니다. 다른 물질의 Lot을 연결할 수 없습니다. 같은 원료를 다른 역할·시점·Lot으로 여러 번 사용하는 것은 서로 다른 사용 행으로 허용합니다. 재고는 API에서 자동 차감하지 않습니다.

## 기존 데이터 이전과 보존

승인된 계정으로 연결하면 첫 사용 시 기존 원료 원본을 `isnm-material-library-before-shared-v1`에 보존하고 공용 자료와 대조합니다. 기존 실험 원본 저장 키는 초기화하거나 삭제하지 않습니다. 공용 실험 연결에는 원본 스냅샷을 저장하며 첨부 파일의 바이너리를 자동 업로드하지 않습니다.

원료 ID 또는 유일한 CAS·정확한 명칭으로만 연결하며, 중복 후보나 불일치는 검토 목록에 남깁니다. 사용자에게 입력받지 않은 물질을 문자열에서 임의로 새 원료로 생성하지 않습니다. 브라우저별 순번이 같은 실험은 사용자·작업 기기·기록 종류를 함께 사용해 충돌을 방지합니다. 저장된 원본 값은 덮어쓰지 않고, 공용 사용 기록에 확정된 참조를 보관합니다.

실제 이전 건수는 각 사용자가 이전에 기록을 저장한 브라우저로 접속한 뒤 표시되는 연결 상태와 검토 목록에서 확인합니다. 배포 시점에 해당 브라우저의 개인 저장 내용을 미리 읽거나 임의로 이전 완료라고 보고하지 않습니다. 이전이 실패하면 원본을 유지하고 재시도를 안내합니다.

계산 기록과 조성 버전은 계획량만 생성합니다. 합성의 명시적 실제 사용량, 또는 실제 합성 배치의 실제량 입력만 실제 사용 기록을 생성합니다. 실제 원료·Lot이 계획과 달라지면 계획과 실제를 서로 다른 참조 행으로 보관합니다.

## 검증

`npm run test:connections`는 SQLite와 실제 API 코드를 사용해 다음을 검증합니다.

- DBU ID와 실제 Lot을 연결하고 함량을 저장·다시 조회
- 촉매 요약/원료 행 중복 방지와 같은 세척액의 반복 투입 구분
- 원료→합성 기록 및 기록→원료 양방향 참조
- 원료 기본 물성 변경 후 과거 스냅샷 불변
- 계획만 저장했을 때 실제 사용량이 생성되지 않음
- 실제 원료·Lot 변경, 다른 물질의 Lot 차단 및 DB FK 검사
- Lot 미등록 시약의 재고·비고 보존과 반복 이전의 멱등성
- 중복 이름·미등록 텍스트를 임의로 연결하거나 생성하지 않음
- 자체 합성 원료 한 종류에 서로 다른 합성 배치 Lot 연결
- 사용 기록 저장 후 잔량이 자동 차감되지 않음

기존 계산기·원료·검색·캘린더 검사도 유지합니다. 브라우저에서 로그인한 실제 사용자의 모든 클릭 동작을 대신 실행한 검증은 포함하지 않습니다.

## 연결 범위와 남는 검토

프로젝트·계산·합성 원본과 첨부 파일은 기존 브라우저 저장 방식도 유지합니다. 공용 서버에는 원료 기준 데이터와 관련 사용 이력·원본 스냅샷을 연결합니다. 기존 프로젝트 저장소 전체나 파일 저장소를 공용 시스템으로 교체한 것은 아닙니다.

자유 서술 메모 속 화학명은 자동으로 해석하지 않습니다. 등록된 측정/분석 원본이 없이 외부 분석 ID만 입력된 경우 해당 외부 데이터는 여전히 참조 텍스트이며, 원본을 등록해야 분석→샘플→합성→원료 역추적이 완성됩니다. 이름이 모호하거나 기존 Lot을 확정할 수 없는 자료는 연구자의 검토가 필요합니다.
