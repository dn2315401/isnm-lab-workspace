## 로컬 실행

Node.js 22 이상이 필요합니다.

```bash
git clone https://github.com/dn2315401/isnm-lab-workspace.git
cd isnm-lab-workspace
git switch work/2026-11-24-v1
npm ci
npm run dev
```

터미널에 표시되는 개발 서버 주소를 브라우저에서 엽니다. 기본 주소는 `http://localhost:5173`입니다.

```bash
npm run test:calculator # 계산·검증 테스트

```

DP811A 장비·매뉴얼·업로드·실제 실험 기록 구현은 [장비 추가 보고서](docs/DP811A_EQUIPMENT.md)를 참고하세요.

날짜 입력 전수 점검·공통화 결과는 [날짜 입력 점검 보고서](docs/DATE_INPUT_AUDIT.md)를 참고하세요.

## 공동 개발

1. 저장소 소유자가 Settings → Collaborators에서 공동 제작자의 GitHub 계정을 초대합니다.
2. 각자 저장소를 clone하고 작업 브랜치를 만듭니다.
3. 변경 후 계산 테스트와 빌드를 실행합니다.
4. 브랜치를 push하고 Pull Request로 변경 사항을 검토합니다.

```bash
git switch -c feature/my-change
# 파일 수정 후
npm run test:calculator
npm run build
git add .
git commit -m "Describe the change"
git push -u origin feature/my-change
```

이 저장소는 소스 코드 공유용입니다. GitHub에 push하거나 PR을 병합해도 위의 Sites 웹앱이 자동 업데이트되지는 않습니다. 현재 자동 배포 연동은 설정되어 있지 않습니다. Vite 빌드 산출물은 `dist/`이며 정적 호스팅 서비스에 배포할 수 있습니다. Sites 프로젝트 식별 정보와 D1 연결은 `.openai/hosting.json`에 있습니다. 현재는 Worker 서버와 D1을 사용하므로 정적 파일만 배포하면 공유 캘린더·원료 API는 작동하지 않습니다.

## 데이터와 계산의 범위

프로젝트, 조성, 예약, 계산 이력, 합성·샘플 계획은 각 브라우저의 `localStorage`에 저장됩니다. 저장소를 함께 사용해도 서로의 연구 데이터가 동기화되지는 않습니다. 여러 사람이 동일한 실험 데이터를 편집하려면 인증과 공유 데이터베이스를 추가해야 합니다.

예시 원료와 물성은 UI 확인용입니다. 실제 연구 결과가 아니며 실험 전 분자량·밀도·원료 Lot·작용기 정보를 확인해야 합니다. 필요한 물성이 없으면 추정값을 사용하지 않습니다. 질량 직접 입력은 입력 합계를 유지하며, 목표 총량에 대한 스케일링은 사용자가 비례 조정 버튼을 누를 때만 수행합니다.

실제 장비 연결, 로그인, 분석 파일 업로드, 실험 완료 처리는 포함하지 않습니다. API 키·환경변수·실험 데이터는 저장소에 커밋하지 마세요.

## 연구실 공유 캘린더 (v3)

홈 상단 연구실 일정과 하단 장비 예약을 분리했습니다. 연구실 일정은 ChatGPT 로그인·구성원 승인·서버 D1 저장을 사용합니다. 개인 공개/비공개, 전체 일정, 반복 회차별 수정·취소, 월·주·일 보기와 수업 시간표를 지원합니다. 기존 실험 기록과 장비 예약은 기존 브라우저 저장 방식을 유지합니다.

관리자는 캘린더의 구성원 관리에서 실제 계정 이메일을 허용하거나 로그인 대기 계정을 승인합니다. 배포 환경의 `CALENDAR_OWNER_EMAIL`은 Sites 설정에서 관리하며 저장소에는 넣지 않습니다. 로컬 Vite 개발 서버는 화면 개발용이며, 실제 인증·공유 API는 Sites Worker 배포에서 제공됩니다. 로컬 서버 로직은 `npm run test:calendar`로 SQLite를 사용해 검증할 수 있습니다.

## 전역 물질 연결 (2026-11-24 v1)

원료·Lot은 공용 D1 DB를 기준으로 선택합니다. 촉매·용매·세척액·조성·실제 합성 입력은 공통 원료 선택창을 사용합니다. 과거 물성은 스냅샷으로 유지하고, 계획량과 실제량을 구분합니다. 자체 합성 원료는 완료 배치를 명시적으로 등록하여 원료 종류와 배치별 Lot을 구분합니다. 재고 자동 차감은 사용하지 않습니다.

승인된 연구실 계정으로 로그인하면 기존 브라우저 원료를 백업·대조하고, 확실한 참조만 연결합니다. 중복 후보는 검토 목록에 남습니다. 실험 원본과 첨부 파일은 브라우저에서 삭제하지 않습니다.

- `npm run test:connections`: 실제 SQLite의 물질·Lot FK, DBU 연결, 양방향 사용 이력, 스냅샷, 계획/실제, 미등록 Lot 재고 보존 검증
- `npm run check:materials`: 원료 API 타입 검사
- [변경 영역·DB 관계·이전·검증·제한 사항](docs/MATERIAL_CONNECTIONS.md)
